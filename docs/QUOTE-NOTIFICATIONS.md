# Quote email delivery

AUTO-003 delivers existing ORD-005 notices without changing their in-app audiences. A buyer recipient is the active member whose exact Base email equals the immutable account email. Staff recipients are every active owner/admin except the actor. Missing buyers produce withdrawn delivery evidence and an owned failed-contact task. Agents and rep profile metadata grant no mail authority. Internal notes can never be addressed to buyers.

The email contains only the notice summary, quote ID and configured HTTPS `/app?quote=<id>` link. Normal sign-in and existing company authorization remain required. No message text, attachment, token, tracking or new outreach grant is included.

Per-user delivery rows are queued atomically with notices. Dispatch checks current authority again and saves the exact address used. Expiry is email-only, once per latest proposed, unaccepted revision and recipient on its last valid America/New_York date. The hourly scheduled handler and supplier dispatch command recheck eligibility immediately before submission; superseded, pending approval, accepted and late reminders withdraw.

Submission requires Resend, API key, sender, HTTPS origin, `MAIL_EVENT_TENANT` and `MAIL_WEBHOOK_SECRET`. Development reads **not sent (development)**; missing configuration reads **email not configured**. A stable delivery ID is the provider Idempotency-Key. Provider acceptance is never labelled delivery. Delivered means delivered to the recipient mail server, never read. The exact provider message ID is retained; a missing ID reads **accepted (uncorrelated)**. Rate-limited and uncertain requests reuse their immutable request and key within 24 hours only. After that they create contact work without resending.

Configure the Resend webhook at `/api/barrow/quote-mail/webhook`. Its POST-only, 1 MiB door uses unmodified Base signature verification, a 300-second freshness window and D1 receipt store. The server-configured tenant, exact saved provider message ID and every saved recipient must match; a signature alone does not authorize an event. Identical replay has no duplicate effect; foreign or changed-fingerprint events are refused. Terminal bounce, complaint and rejection suppress further sends to that exact address. Open and click events are ignored.

Failed-contact tasks are keyed by quote and recipient user. Buyer failures start with the active latest proposer, otherwise the installation owner; staff failures start with the owner. Repeated facts attach to the same task. Dates use New York. Contact attempts and assignment use the existing revision-guarded staff commands. Acceptance, refresh, later delivery and revisions never resolve contact work; explicit attributed resolution does. Diagnostics show open non-success delivery IDs, states, ages, owners and task links without message bodies or secrets.

Owner archives retain ledger, tasks and Base receipts/states, but exclude credentials and the secret fingerprint. Restored pending/uncertain rows are uncertain and never resubmit; historical notices cannot enqueue new mail. Reconnect Resend and re-enter the webhook secret after restore. Secret configure/rotate/revoke, verified events and contact work record secret-free system audit events. Supplier-only `quotedeliveries` JSON/CSV carries durable evidence; buyer exports omit it. Saved addresses use the messages retention kind; provider copies remain separate mail custody. Unused-account erasure removes matching ledger, task and event records under the existing restore fence. Broader message erasure remains DATA-003 partial.
