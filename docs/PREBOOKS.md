# Seasonal prebook intake

Use native seasonal orders for the complete release and payment journey. This page describes the separate command-only intake API. The command API supports seasonal intake and guarded future demand commitments. It does not yet support supplier acceptance, release to Pier, backorder changes, seasonal report rows or the buyer and operations screens. A deposit is an exact-cent requirement, with collected amount unknown; these commands never create a payment, allocation, stock reservation or invoice. PAY-003 retains collection and allocation.

The supplier owner or admin publishes an immutable season using `prebook.season`: `id`, `name`, timezone-qualified `opensAt` and `closesAt`, integer `depositBps` and a reason. Opening is inclusive and closing exclusive. `prebook.close` takes the season ID, current revision and a reason, and records the closing person and time. Publish another season to change its commercial settings.

A current company purchaser calls `prebook.prepare` with `accountId`, optional `profileId`, `seasonId` and lines. Each line supplies SKU, selling unit, quantity, future `requestedDate` and `cancelAfter`. Normal current account and profile pricing, selling-unit conversions, quantity rules and account minimums apply. The returned draft freezes seller, ISO currency, integer line amounts, base quantities and the deposit requirement. Deposit rounding is nearest cent, exact half cents up.

Call `prebook.commit` with `prebookId` and the reviewed revision, plus the usual sales-terms acceptance when assigned. Commitment rechecks current profile approval, account revision, units, prices, stock freshness and dated incoming supply. Replaying a committed request returns its recorded snapshot without another effect. Supplier staff cannot stand in for the company purchaser. Company approval routing and location-scoped prebooks remain unimplemented; requests needing them are refused, preserving existing company authority.

Capacity comes only from unreceived quantities on committed Pier purchase orders with a known receiving warehouse and a recorded promise date no later than the requested ship date. Available-now stock stays separate. Existing committed demand across all accounts and seasons is deducted using its frozen warehouse scope. The shared native commitment epoch prevents two concurrent admissions from spending the same remaining capacity. This is future demand, not an inventory reservation; Pier remains the stock authority. Incoming changes can prevent later admissions; release-time reconciliation remains unimplemented.

`GET /api/barrow/prebooks/{id}` serves the snapshot to an authorized company purchaser or approver and to the supplier owner or admin. Ordinary order edits, shipping selection, cancellation and invoice downloads cannot address these separate prebook IDs. Company-scoped commercial export includes prebook snapshots in JSON and `prebooks.csv`; its manifest counts them separately. Owner archives retain the records and restore seasonal intake inactive. Accounts with prebook history cannot use unused-account erasure. This command-only intake API has no release door; use native seasonal orders for the complete fulfillment journey.

Native seasons use `prebook.publish` and `/api/barrow/prebook-seasons`; their closing command uses the settings revision. Intake seasons use `prebook.season`; their closing command uses the intake season revision. Both admission doors share the native commitment epoch and deduct commitments from the other door before admission, so they cannot independently spend the same incoming supply. Migration `0065_prebooks.sql` adds intake custody without modifying existing migrations.

Intake records participate in the existing owner erasure review and its whole-table fingerprint. Draft and expired personal details are redacted, current committed commercial snapshots retain the existing seven-year floor, and the independent journal reapplies the reviewed operation before restored product reads. Company-user erasure also redacts identifying text while retaining opaque commercial attribution.
