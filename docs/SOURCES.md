# Source lineage and boundaries

Barrow was generated and composed from committed Base `fc0e1041efa55771142bbb57c4ab4743147e264d`, then converted to package mode. It now pins exact `@runeditrun/rer` 0.2.21. `composition.lock.json` records the original source copies. Base's operator auth, development mail, first-run flow, theme, portability and D1 import-kit are reused. The copied import-kit source and schema come from that same Base revision. Application changes live under `src/barrow`; no sibling source repository is modified.

- [Pier orders](https://github.com/just-every/run-pier/blob/dcd4c5916a96b3237eafbec6abd6591df5c75dcd/src/pier/orders.ts), [catalogue](https://github.com/just-every/run-pier/blob/dcd4c5916a96b3237eafbec6abd6591df5c75dcd/src/pier/catalogue.ts) and [native reservations](https://github.com/just-every/run-pier/blob/dcd4c5916a96b3237eafbec6abd6591df5c75dcd/src/pier/native-reservations.ts): `src/barrow/pier.ts` adapts Pier's decimal string conversion and consumes its real state and idempotent order command. Reservation logic stays in Pier. Native reservation import remains a Pier migration operation, not a checkout shortcut.
- [Orbit account repository](https://github.com/just-every/run-orbit/blob/38cef87571a413802dbaa7aa6afbab332d8cd778/src/core/features/records/repository.ts): account associations are explicit stable IDs and verified email identities, adapted to one trade buyer email per account. Barrow stores the exact Pier party ID, never a fuzzy company-name match.
- [Nectar receivables](https://github.com/just-every/run-nectar/blob/c76a60ccffa39cc1a207b52c152bda16d6d7b1df/src/nectar/receivables.ts): the invoice handoff follows integer-cent commercial values and separates issue/due dates from payment. It does not record payments or duplicate Nectar's receivables ledger.

The initial stock adapter requires a current Pier operator session because that release has no dedicated service credential. Expiry is an explicit connection failure. Only the server sees it; customer catalogue responses contain permitted SKU data and prices. Stock displayed before approval is an observation, not an allocation. A stable request identity recovers uncertain Pier outcomes, and invoices require every line reserved.

The published RER package supplies the command lifecycle and static run-site build and deployment. No local RER patches are applied. The run site renders the Markdown in this `docs/` directory at build time; guides are maintained here alongside the code.
